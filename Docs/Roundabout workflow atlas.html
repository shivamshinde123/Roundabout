Product rules used in this document

  • One human owner per workspace in the first release. A workspace has projects, projects have boards, and each task has one home board.
  • People sign in with email and password or Google. Agents connect separately and receive access to selected projects. Codex and Claude Code are first to verify.
  • Assigned tasks wait until the agent is opened and checks for work. The agent accepts before the board moves the task to In Progress.
  • A handoff keeps the current owner until the recipient accepts. Each task can require human approval or allow completion by the agent.
  • The board and agent interface enforce the same permissions and update the same task history in PostgreSQL.

Design assumptions. Where the requirements leave details open, the diagrams propose retry behavior, conflict handling, and recovery paths. Blocked can be a visible card state or a column. The default review setting, exact access rules for future teammates, client-specific capabilities, and timing policies remain open.

Reading the diagrams. Follow the numbered boxes down the left. A box on the right describes what happens when the condition in that box applies. A branch may end the current attempt, return to an earlier step, or link to a related workflow.
